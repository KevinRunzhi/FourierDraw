## 一、一句话描述

手绘任意图形,用一串旋转的圆把它重新画出来。

## 二、项目背景与约束

本作品用于 SCC 小组赛,提交后由评委离线评审。以下是硬约束,任何设计决策都不得违反:

| 约束项 | 具体要求 | 对本项目的影响 |
|---|---|---|
| 交付形式 | 必须是 App Playground(`.swiftpm`) | 不建 Xcode 项目;Xcode 仅作为编辑器打开 `.swiftpm` |
| 网络 | 离线评审,不可依赖网络 | 零网络请求,零远程资源 |
| 资源 | 全部资源内置于 ZIP 内 | 无图片、无音频、无字体文件;所有画面实时计算生成 |
| 体积 | ZIP ≤ 25 MB | 预估实际体积 < 500 KB,无压力 |
| 体验时长 | 三分钟内可完整体验 | **无欢迎页、无教程页、无登录**,打开即有动画 |
| 附加文档 | 200 字以内 PDF 文字说明 | 见第十一节 |

评分维度:功能完整性 3 分、技术难度 3 分、创意性 2 分、呈现效果 2 分。本文档第九节说明每个维度的对应设计。

## 三、目标与非目标

### 3.1 产品目标

让一个完全不懂傅里叶变换的人,在三分钟内亲眼看懂一件事:

> 任何一条闭合曲线,都可以拆解成若干个不同大小、不同转速的圆的旋转叠加。

这不是通过文字解释达成的,而是通过一个可以拖动的滑块——用户自己动手把图形从最基础的椭圆轮廓一路"长"到完整形状,理解在这个过程中自然发生。

### 3.2 明确的非目标

以下内容本版本不做,写在这里是为了防止开发过程中范围蔓延:

- 不做账号、云同步、分享、导出视频
- 不做音频合成(把谐波映射成声音),概念好但一天时间性价比低
- 不做二维图像的频域滤波(那是另一个项目)
- 不做 FFT 优化,朴素 O(N²) 足够
- 不做 iPad 分屏、横竖屏双套布局;竖屏优先,横屏能用即可
- 不做深浅色双主题,只做纸本白「墨迹」主题

### 3.3 目标用户

评委(第一位),以及任何在中学接触过三角函数、但没学过傅里叶变换的人。

## 四、核心概念

用户画的一条闭合曲线,可以看作复平面上的一串采样点 z₀, z₁, …, z_{N-1}。对其做离散傅里叶变换,得到 N 个复系数 c_k:

```
c_k = (1/N) · Σ_{j=0}^{N-1} z_j · e^(-i·2π·k·j/N)
```

N = 512 时,唯一频率集合定义为:

```
K₅₁₂ = {-256, -255, …, -1, 0, 1, …, 255}
```

每个 c_k 对应一个圆:

- **半径** = |c_k|(模长)
- **初相位** = arg(c_k)(辐角)
- **转速** = k(下标,需映射到 [-N/2, N/2) 区间,允许负值即反向旋转)

把这 N 个圆按 `0, +1, -1, +2, -2, …, +255, -255, -256` 的固定频率顺序首尾相连——第一个圆的圆心固定,它的边缘点作为第二个圆的圆心,依此类推——所有圆同时按各自转速旋转,最末端那个点划过的轨迹,恰好还原出原始曲线:

```
z(t) = Σ_k c_k · e^(i·2π·k·t)
```

阶数滑块控制标准的双边傅里叶部分和:

```
S_M = { k ∈ K₅₁₂ | |k| ≤ M }
f_M(t) = Σ_{k ∈ S_M} c_k · e^(i·2π·k·t)
```

其中 M ∈ [1, 256]。M ≤ 255 时参与项数为 `2M + 1`;M = 256 时因不存在独立的 `+256` 频率,共 512 项。质心归零后的 `c₀ ≈ 0` 仍保留在完整 DFT 中。M = 1 时由 `-1, 0, +1` 三项合成的轨迹通常是椭圆,也可能退化为圆或线段。

**谁参与计算**由 `|k| ≤ M` 决定;**圆链如何排列**由上述固定频率顺序决定。两者不得再与「按振幅取前 M 项」混淆。

## 五、功能需求

### 5.1 优先级定义

- **P0**|不做就不能交付,必须完成
- **P1**|直接影响评分,强烈建议完成
- **P2**|锦上添花,时间不足时第一批砍掉

### 5.2 功能清单

#### F1 · 开屏自动演示(P0)

应用启动后立即播放内置预设图形的本轮动画,无任何点击门槛。

- 默认预设:五角星(单笔闭合的 10 顶点轮廓,用代码直接生成;轮廓清晰,圆链运动感强)
- 屏幕底部常驻一行提示文字:「用手指画一个封闭图形试试」
- 提示文字在用户第一次绘制后永久消失

#### F2 · 手绘输入(P0)

- 使用 `DragGesture(minimumDistance: 0)` 采集触摸点
- 绘制过程中实时显示原始笔迹(高饱和色实线)
- 单指绘制,不支持多指
- 所有有效笔迹都视为周期曲线:始终把末点到首点作为闭合段,再沿完整闭环重采样;512 个输出点不重复末端起点
- 抬手后自动触发 F3 计算与 F4 播放
- touch-down 时旧作品在 0.2s 内淡到 15%,但暂不销毁
- 采样点少于 10 个时视为误触,不触发计算;旧作品淡回原状并恢复播放
- 只有新笔迹有效时才替换旧作品;成功手绘后阶数重置为 M = 256

#### F3 · 傅里叶分解(P0)

抬手后一次性执行,全过程应在 100ms 内完成:

1. 等弧长重采样至 N = 512 点
2. 平移点集使质心位于原点
3. 翻转屏幕坐标的 y 轴,使数学坐标中的正频率在画面上逆时针旋转
4. 转换为复数序列,执行 DFT
5. 把索引映射到 `K₅₁₂`,输出按 `0,+1,-1,+2,-2,…` 固定顺序排列的 `[Epicycle]`
6. 记录统一渲染变换,把原稿幽灵与重建结果一起居中、等比适配内容框

**等弧长重采样是必须的**。用户画得快的地方点稀、画得慢的地方点密,直接送入 DFT 等于给曲线加了非均匀的时间参数化,重建结果会变形。

#### F4 · 本轮动画渲染(P0)

- 使用 `TimelineView(.animation)` + `Canvas` 实现,目标 60fps
- 每个圆绘制:低透明度灰色圆环 + 稍亮的半径连杆
- 使用 `timeline.date` 计算统一的归一化时间 t,圆链、解析笔尖和正弦条共用同一个 t
- 末端笔尖位置由当前部分和直接解析计算,始终精确;历史轨迹由固定采样缓存连接为折线,属于可降级的视觉近似
- 动画采用「起稿 → 运笔 → 收笔 → 翻页」编排:起稿 0.9s、收笔 0.8s、翻页 0.5s;运笔在冷启动/预设/后续循环为 6s,仅用户成功手绘后的第一轮为 12s
- 拖动阶数时立即取消当前收笔、落印或翻页,进入稳定运笔态;松手后先走完当前一圈,再正常进入收笔和翻页,不补播被取消的落印
- 半径小于 0.5pt 的圆不绘制圆环和连杆,但仍参与位置计算

#### F5 · 频率阶数滑块(P1,教学核心)

**这是整个作品最重要的交互,优先级仅次于 P0 主链路。**

- 滑块范围 M = 1 ~ 256,默认值 256(完整还原)
- 拖动时实时改变标准部分和的参与集合 `S_M = {k ∈ K₅₁₂ | |k| ≤ M}`
- 主标签格式:「阶数 |k| ≤ 128」;辅助信息与 VoiceOver 可补充「共 257 项参与」,参与项数必须从实际集合计算
- 采用非线性映射,低段更细腻:滑块位置 p ∈ [0,1] 映射为 `M = round(1 + 255·p²)`
- 状态中保存连续的滑块位置 p,渲染时再计算整数 M,避免整数值反向映射造成拖动跳变
- 拖动过程中不重新计算 DFT。M 增大时按跨过的频带增量加入 `±k`;M 减小时合流到每帧一次目标缓存重建;松手后完整重建一次,清除累计浮点误差
- M 改变后保持当前时间相位,用新 `S_M` 立即更新从周期起点到当前时刻的轨迹,不得混合旧、新阶数的墨迹

#### F6 · 预设图形画廊(P1)

底部一排图标按钮,点击后直接加载对应预设并播放:

| 预设 | 优先级 | 选择理由 |
|---|---|---|
| 五角星 | P1 | 默认展示项,尖角多,圆链运动漂亮 |
| 心形 | P1 | 可用参数方程生成,曲线光滑,与星形对比明显 |
| 正方形 | P1 | **教学关键项**,展示低频负责轮廓、高频补出直角与细节 |
| 汉字「数」 | P2 | 仅作为时间充足时的加分项,展示复杂曲线的还原能力 |

所有预设均由 Swift 代码内置生成或声明,不使用 JSON、不读取 Bundle 资源。Swift Playgrounds 的资源路径行为不稳定,不值得为此排查。

首版只验收五角星、心形、正方形三个预设。汉字「数」不进入首版验收;三个预设完成后仍有余量再考虑实现,不预先制作替代项。

手动切换预设时保留当前 M,便于同阶比较;加载新预设时退出手动选频,回到自动正弦项。空闲轮播若实现,遵循同一规则。

#### F7 · 频谱条形图(P1)

屏幕底部区域,横轴为频率 k、纵轴为 |c_k| 的条形图。

- 固定显示 `k ∈ [-32, 32]` 共 65 根柱,按真实频率从左到右排列;正负频率的位置对称,振幅不保证对称
- 柱高在当前可见 65 项内线性归一;启用态由 `|k| ≤ M` 判定,因此高亮带从 k = 0 向两侧连续扩张
- M > 32 时在两端显示溢出标记,并按实际集合显示窗口外参与项数;M = 256 时为 447 项
- 整张频谱使用容器级点击/横向拖动手势,按 x 坐标吸附最近 k;VoiceOver 暴露为可调节控件,逐项朗读频率、振幅和参与状态
- 频谱可视化是硬验收;手动点击切换观察项是 P1 目标,若命中交互阻塞交付可独立回退,不得拖累 F8 自动模式

#### F8 · 旋转到正弦(P1,教学核心)

- 正弦条默认常驻,无需点击即可建立「旋转 → 投影 → 正弦」关系
- 自动模式从 `min(M, 32)` 向 1 递减扫描频率对;阈值基准为当前参与集中非零频率的最大振幅,找到首个 `max(|c₊k|, |c₋k|) ≥ 1e-3·a_max` 的频率对后,展示对内振幅较大的一项;全部为零时回退到 k = 0 注脚
- 正弦条横轴固定显示所选项的两个完整局部周期;动点仍以真实 k 与主动画共享 t。自动范围限制在 `|k| ≤ 32`,不提供高频手动入口,避免不可见高频的时间混叠
- 选中项的小圆与波形使用同一放大倍数,同时标注真实半径及「波形已放大」;主圆链保持真实比例
- k = 0 时显示静态点与说明:「零频不旋转,表示中心偏移;当前已归零」
- 自动模式不使用朱砂、不展开单项公式、不高亮圆;只有用户手动选择后才进入单项展开态
- 用户可主动查看当前 `S_M` 外的可视频率项:公式与正弦条正常展示,圆链不高亮,并提示「阶数不够,这一项还没加进来」
- 手动选择跨动画循环保留;再次点击同一柱、点击画布空白、切换预设、空闲轮播或成功手绘时恢复自动模式
- 若已选项从上一帧参与变为当前帧不参与,立即恢复自动模式;选中时本就未参与的项不受此规则影响

#### F9 · 正方形高频提示(P2)

当用户进入「正方形」预设且 M ≤ 32 时,本次进入最多淡入一次:

> 低阶只画得出圆滑的东西,直角是高频堆出来的

切换到其他预设或成功手绘即视为离开;再次进入正方形可再次显示。本文案只讲频率与细节,不把连续方形轮廓误称为经典吉布斯现象。

#### F10 · 空闲预设轮播(P2,第一砍项)

- 仅当当前内容来自预设时,20 秒无操作后切换到下一个预设,0.5s 交叉淡入
- 用户手绘作品绝不被轮播覆盖
- 轮播保留 M,退出手动选频并回到自动正弦项

#### F11 · 播放控制(P2)

暂停/继续按钮、速度调节(0.5× / 1× / 2×)。有则更好,无则不影响。

#### F12 · 方波吉布斯加餐(P2,条件启动)

仅在所有硬验收、连续缩放测试和打包演练全部通过,且功能冻结前仍有至少 1 小时余量时启动。复用正弦条渲染奇次谐波 `1/1, 1/3, 1/5, …`,展示真正有跳跃不连续点的方波部分和及约 9% 超调标记。该功能必须隔离实现,可瞬时回退;除此之外不新增加餐。

## 六、交互流程

### 6.1 三分钟体验脚本

评审是限时的,体验节奏本身需要设计:

| 时间 | 用户所见 |
|---|---|
| 0:00–0:15 | 打开即以 6 秒常速播放五角星预设;公式、频谱和紧凑正弦条同时可见。底部提示「用手指画一个封闭图形试试」 |
| 0:15–0:45 | 用户画一笔,有效收笔后原稿幽灵与重建一起居中适配,圆链展开并以 12 秒慢速完成第一轮揭晓 —— **本作品的高光时刻,必须干净利落** |
| 0:45–1:30 | 用户把阶数拖到最左端,只剩最基础的椭圆轮廓;再向右拖到 `|k| ≤ 256`,直角和细节由更高频率逐步补出 —— **教学价值所在** |
| 1:30–2:15 | 观察 `-32…+32` 频谱从中心向两侧点亮;正弦条同步展示一个旋转项的投影 |
| 2:15–3:00 | 点击频谱柱查看单项,再切换心形与正方形,比较相同阶数下的轮廓细节 |

### 6.2 状态机

```
playing(播放预设或用户作品)
  ├─ 手指按下 ──→ drawing(旧作品淡到 15%,显示实时笔迹)
  │                   ├─ 误触 ──→ playing(旧作品恢复)
  │                   └─ 有效抬手 ──→ computing(< 100ms) ──→ playing(首轮运笔 12s,M=256)
  ├─ 点击预设 ──→ computing ──→ playing(运笔 6s,保留 M)
  ├─ 拖动阶数 ──→ interactivePlaying(取消装饰阶段,更新 S_M 与轨迹缓存)
  │                   └─ 松手 ──→ 走完当前运笔圈 ──→ 收笔/翻页 ──→ playing
  └─ 手动选频 ──→ selectedTerm(主动画继续,正弦条共享 t)
```

`computing` 状态耗时极短,不需要 loading 指示器。

## 七、视觉设计

视觉规格以 `FourierDraw_DESIGN_BRIEF.md` 为唯一准绳。采用纸本白 + 墨黑 + 朱砂的「墨迹」方向,不再实现早期的深色青光方案。

| 元素 | 规格 |
|---|---|
| 背景 | 冷纸白 `#F1F0EC` |
| 圆环 / 连杆 | 石墨灰低对比构造线;不承载必须辨认的信息 |
| 重建轨迹 | 墨黑,线宽稳态 2.0;高性能档保留湿墨头 |
| 用户实时笔迹 | 石墨灰,线宽 3.0;有效收笔后以 12% 透明度成为原稿幽灵 |
| 频谱与文字 | 墨色层级区分启用/未启用;朱砂只表示用户正在操作或手动选中的量 |
| 字体 | 系统 SF Pro + New York 设计变体,无自定义字体资源 |

纸页铺满全屏,控件浮在内容之上,不采用固定 65/35 分区。宽度 < 500pt 时上下叠层,正弦条在公式下方使用约 64pt 紧凑布局;宽度 ≥ 500pt 时画布居左,公式、正弦条与控件进入右侧内容栏。主展示基准为 iPad/常规宽度,iPhone 必须完整可用;Mac Playgrounds 窗口从最窄连续拖到最宽时不得出现截断、重叠或公式崩版。

## 八、技术方案

### 8.1 技术栈

只用 `SwiftUI` 和 `Foundation` / `CoreGraphics`。**禁止**:UIKit、Metal、`.metal` 文件、SPM 外部依赖、asset catalog、Bundle 资源读取、Info.plist 自定义项、第二个 target。

目标 iOS 17,不使用任何 beta API。

违反上述任一条,都可能制造一个只在最后打包时才暴露的问题。

### 8.3 核心数据结构

```swift
struct Complex {
    var re: Double
    var im: Double
    var magnitude: Double { sqrt(re*re + im*im) }
    var phase: Double { atan2(im, re) }
}

struct Epicycle {
    let freq: Int       // 转速,可正可负
    let amp: Double     // 圆半径 = |c_k|
    let phase: Double   // 初相位 = arg(c_k)
}
```

### 8.4 关键实现要点

**负频率映射**|索引 `k >= N/2` 的项必须映射为 `k - N`。N = 512 时索引 256 必须得到 `freq = -256`;条件写成 `>` 会制造不存在的 `+256`。

**固定频率顺序**|圆链按 `0,+1,-1,+2,-2,…` 排列。M 增加时新频率只追加到链尾,已有圆心保持不动;`±k` 相邻也让正反旋转直接可见。频谱柱高仍使用振幅,但不得再按振幅重排圆链。

**参与项、频谱窗口与圆环预算分离**|所有 `S_M` 项参与解析笔尖计算。频谱固定显示 65 项(`-32…32`);圆环在半径 ≥ 0.5pt 的前提下,高档最多绘制 120 个非零频圆环(约到 `|k|≤60`),低档最多 60 个(约到 `|k|≤30`)。三套数字不得相互替代。M = 256 时频谱窗外有 447 项参与;圆环未绘制的项另行计算,不出现在用户文案里。

| 独立预算 | 高档 | 低档 | M = 256 时的口径 |
|---|---|---|---|
| 频谱窗口 | `-32…32`,65 项 | 相同 | 窗口外 447 项仍参与;这是用户可见的溢出数 |
| 圆环绘制 | 最多 120 个 | 最多 60 个 | 至少 392 / 452 项不画圆环(含 `c₀`);0.5pt 阈值可能使实际绘制数更少 |
| 历史轨迹 | 1024 点折线 | 512 点折线 | 只影响视觉近似;解析笔尖不降级 |

**动画时间**|使用 `TimelineView` 提供的 `timeline.date` 计算相位,不自行维护帧计数器,避免掉帧导致动画速度漂移。

**轨迹缓存**|高档使用 1024 个空间样本,低档使用 512 个。1024 点使最高 `|k|=256` 仍有 4 倍空间过采样;360 点会在 `|k|>180` 时混叠,禁止使用。M 增大时按嵌套集合增量加入跨过的频带;M 减小时按帧合流重建;松手后全量重建一次。每帧末端笔尖另用解析式计算并追加,避免缓存折线与圆链末端错位。

**质量档测量**|冷启动起稿结束后丢弃 10 帧,测量后续 30 帧;排序后的第 27 帧(p90)≤16.7ms 选高档,否则选低档。初测后仅当容器面积相对测量基准增长超过 1.5 倍、且尺寸稳定 300ms 时允许重测一次;同样丢 10 帧、测 30 帧,只允许从高档降到低档。低档同时关闭湿墨头分段渲染,改为单段等宽 Path;始终维持 60fps 请求,不动态来回切档。

## 十二、验收标准

### 12.1 数学层验证(必须最先通过)

构造半径 100、圆心在原点、数学坐标逆时针的标准圆 512 个等角采样点,输入 `dft`:

- 预期:仅 `freq == 1` 的项 `amp ≈ 100`,其余所有项 `amp < 1e-6`
- 屏幕坐标中顺时针绘制的同一圆,翻转 y 轴后应仅有 `freq == -1` 的主项
- 单独验证索引 256 映射为 `freq == -256`,即条件必须是 `k >= N/2`
- 若不通过,检查 y 轴翻转、频率映射与指数符号

`resample` 验证:输入边长 100 的闭合正方形四个顶点,按循环路径重采样至 8 个不重复点,预期依次为 `(0,0)、(50,0)、(100,0)、(100,50)、(100,100)、(50,100)、(0,100)、(0,50)`。

部分和验证:M = 1 时仅纳入 `{-1,0,+1}`;M = 255 时为 511 项;M = 256 时追加唯一的 `-256`,总数为 512。不得生成 `+256`。

**数学层不过,后续所有视觉问题都会指向错误方向,必须先验。**
