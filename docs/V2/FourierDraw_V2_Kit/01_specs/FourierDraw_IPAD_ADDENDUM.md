## 一、为什么改

评委在 iPad 上打开。原「常规宽度」稿把公式、正弦条、浮层面板压进右侧 320pt 一栏，本质是把窄屏布局贴到了 iPad 边上；65 根频谱柱挤在 288pt 内，柱心间距 5pt，读不出也点不准。

同时收到的反馈是「像在玩动画，不知道原理」。诊断：符号与画面之间**没有一条可见的对应线**，而且滑块只能连续拖，看不清一阶一阶到底加了什么。

Apple 在 WWDC26 的设计原则里有一条正好适用：简单不等于极简，有时候让界面更简单意味着往里**加**上下文和信息，人才能做出有依据的判断。本次改动全部是加信息，不是减。

## 二、iPad 横屏布局（基准 1180 × 820 pt）

```
24                    704 740                          1156
 ┌─────────────────────────────────────────────────────┐ 24
 │ 圆之绘                                               │
 │ 手绘任意封闭图形，用一串旋转的圆重新画出来              │
 ├─────────────────────────────────────────────────────┤ 92  发丝线
 │                          │                          │
 │      画布 680 × 488       │   公式 + 逐符号释义        │ 112
 │      圆链中心 (364,356)   │   ───────                │
 │      形状半径 150         │   正弦条（波形区 342pt）   │
 │      画布内挂三条          │   ───────                │
 │      符号锚点标注          │   平均偏离（大数字）       │
 │                          │                          │
 ├──────────────────────────┴──────────────────────────┤ 600
 │  阶数 |k| ≤ 6   共 13 项参与        一阶一阶看  ⊖ ⊕   │ 628  浮层面板
 │  ▁▂▃▅▇█▇▅▃▂▁  65 根频谱，柱心间距 17.1pt            │
 │  −32      −16      k = 0      +16      +32          │
 │  ○────────────●────────────○   中心向外的对称滑块     │
 └─────────────────────────────────────────────────────┘ 800
```

三条硬性变化：

1. **频谱与滑块移到底部通栏。** 柱心间距从 5pt 变成 17.1pt。命中测试仍是整条挂一个 `DragGesture` 用 `location.x` 反查最近的 k，不铺热区。
2. **滑块改为中心向外对称生长。** 左侧是镜像的非交互指示点，右侧是真正的 knob，中间一条 k=0 刻度对齐频谱的 0。拖动手势和「高亮带向两边扩张」变成同一套语法。
   *注意*：滑块用 `M = round(1 + 255·p²)`，频谱是线性 k 轴，两者刻度并不严格对齐，这是有意的（低阶需要精细控制）。视觉上传达「对称向外」即可，不要为了对齐去改映射。
3. **画布加宽到 680pt。** 圆链能用满，最外层辅助圆不再贴边。

竖屏与更小窗口沿用原「讲义倒序」规则，本文件只覆盖 `width ≥ 900pt` 的情形。

### 关于 Liquid Glass

**不要动 API。** `.glassEffect()` 是 iOS 26 起才有，与 AGENTS.md 的「目标 iOS 17、不用 beta API、不碰 Package.swift」三条红线冲突，在 DDL 前 36 小时引入必然出事。只吸收原则、不吸收实现：

- 内容铺满，控件抬升于内容之上（纸页延伸到浮层面板背后，这条原稿已经做对了）
- 同心圆角：面板 22，内部控件 6，比例协调
- 左对齐的字号层级替代居中排布

`.ultraThinMaterial` 在 iPadOS 26 上渲染出来是安静而正确的，不会显旧。

## 三、教学层：五个机制

### M1 · 公式解剖标注（约 40 分钟）

画布上挂三条锚点标注，每条是「符号 + 两三个字的大白话」，一条发丝引线指到它命名的那个东西：

| 锚点 | 标注 |
|---|---|
| 最大那个圆的半径线中点 | `cₖ`  半径 |
| 最大那个圆外侧的转向弧 | `e^(i2πkt)`  转速与方向 |
| 圆链末端的连杆簇 | `Σ`  把这些圆首尾接起来 |

右侧公式下方同步列出四行完整释义，符号列用衬线体、释义列用无衬线，符号本身就是两边的对应关系。**不要用 ①②③ 编号**——编号是给序列用的，这里是对应关系，多一层翻译。

引线用 `ink.opacity(0.26)`、1pt，锚点端一个 1.9pt 实心点。

### M2 · 阶数差量高亮（约 50 分钟）

只有按 ⊕ 使 M 从 `M₀` 单步增加到 `M₁` 时触发；⊖、连续拖动、轮播、切预设和手绘完成不触发。900ms 内：

- 新增的 `±M₁` 两个圆用朱砂描边（1.6pt，opacity 0.95）
- 上一条墨迹 `trail_{M₀}` 以 9% 灰留在底层
- 公式下方出现三行：`+2 项` / `k = +4 和 k = −4` / `半径 9.2 pt 与 3.8 pt`
- 平均偏离显示 `14.8 → 11.0 pt`，箭头右边那个数是朱砂

新增项是「当前正被操作的量」，用朱砂符合 §3.1 的第一条用途，不违规。

`trail_{M₀}` 由 `ContentView` 在 ⊕ 更新 M 之前快照现有 `trail` 数组；画布只负责绘制，不重算。

补一行灰字讲清最容易误解的一点：**两边频率对称，半径通常并不相等。**

### M3 · 阶数步进按钮（约 20 分钟）

浮层面板右上角一对 ⊖ ⊕，各 28pt，按一次 `M ± 1`，左边一行 11pt 灰字「一阶一阶看」。

滑块能连续拖，但连续拖动时人只看见形状在扭，看不见加了什么。步进 + M2 的差量高亮组合起来才回答「每个阶数背后是怎样的」。

### M4 · 平均偏离（约 25 分钟）

右侧栏底部三行：

```
墨迹与原稿的平均偏离
5.0 pt                         ← 26pt 衬线
阶数每加一阶，这个数不会变大     ← 11pt 灰
```

算法：`E(M) = sqrt(Σ |c_k|²), |k| > M`。M 或系数变化时遍历现有 512 个 `Epicycle` 计算一次，状态存数学单位；只在 ≥ 900pt 布局使用现有 `paperScale(for:in:)` 转成 pt。

这一条把「逼近」从一种感觉变成一个可读的数字，成本极低。

### M5 · 首轮引导字幕（约 30 分钟）

冷启动后 8 秒内，画布下方浮一张 492 × 52 的半透明卡片，依次出三句，下方三个小圆点标进度：

| 时刻 | 字幕 |
|---|---|
| 0.0 s | 每个圆是求和式里的一项 |
| 2.5 s | 圆首尾相接，末端就是笔尖 |
| 5.0 s | 拖下面的滑块，看它用几个圆 |

**这不是教程页。** 字幕浮在实况画面上，不拦任何交互，任何时候上手都立刻淡出，整个会话不再出现。PRD 3.2 禁的是欢迎页 / 教程页 / 开始按钮，这三样它都不是。

只看 90 秒的评委，这 30 分钟是全项目回报最高的 30 分钟。首轮字幕不做圆链提亮、连杆闪或滑块跳动；字幕自身已完成教学目标。

### 顺带补上的一条

规格里写了「为什么有些圆倒着转是要主动讲的教学点」，但界面上一直没体现。半径 > 26pt 的圆外侧加一段 8pt 的转向弧 + 箭头，正频率逆时针、负频率顺时针。成本近似为零。

## 四、朱砂用量复核

改动后朱砂出现在：滑块旁的活数字 M、拖动时新增的两个圆与对应频谱柱、选中项的圆与柱与单项公式、正弦条上的同步红点、收笔完成印。

全部落在「当前正被操作或选中的量」与「收笔完成印」两条内。**新增的差量高亮 900ms 后必须完全褪回石墨灰**，不允许残留。

## 五、验收补充

- [ ] iPad 横屏下频谱 65 根柱全部可见，柱心间距 ≥ 15pt
- [ ] 从最窄拖到最宽连续缩放，公式区的上下标不错位、不换行崩版
- [ ] 三条画布锚点标注在任何 M 值下都不压住墨迹主体
- [ ] 按一次 ⊕，能同时看到：新圆出现、旧墨迹残影、`+N 项` 文字、平均偏离不会变大
- [ ] 差量高亮 900ms 后朱砂完全褪尽
- [ ] 首轮字幕在任意一次触摸后立即消失，且整个会话不再出现
- [ ] 关闭「减弱动态效果」后字幕仍出现，但不做淡入淡出
