## 每轮的工作循环

```
1. 贴 V2_SCOPE_LOCK.md + 对应的 Prompt
2. 让 Codex 先出 plan，不要让它直接写代码
3. 用下面五条打回标准审 plan
4. 批准，它写代码，输出完整文件不要 diff
5. 编译，零 error 零 warning
6. 在模拟器里肉眼确认 prompt 结尾要求的那个信号
7. 确认通过，才进下一个 prompt
```

**第 6 步不能跳。** 一旦积累两三个未验证的文件，报错会互相掩盖。

### 每一步只改一个文件

跨文件的 prompt（24、25、26）已经拆成有序子步骤，**每一步单独编译、单独确认**，不许合并。
rev.1 里"只有 Prompt 24 可以跨文件"那条规则是错的，已作废。

### plan 阶段的五条打回标准

1. 提到要改 `Package.swift` 或新建 target
2. **单个子步骤**里计划改两个及以上文件
3. 提到要修改 `Math/` 下的任何文件（rev.2 起该目录完全只读）
4. 没写验证步骤，或验证步骤是"应该没问题"这类空话
5. 用了没见过的 API 且没说明来源

批准前问自己：**这个 plan 执行完，我能不能立刻编译并看到一个明确的成功信号？** 答不上来说明范围切太大。

## 四件容易被 Codex 顺手做错的事

**它会想重写 PRD。** 不要。原 PRD 第四节的数学定义和第七节的技术方案已经通过闸门验证，重写等于把地基重挖一遍。规格以增量文件挂载。

**它会想上 Liquid Glass。** 不要。`.glassEffect()` 是 iOS 26 起才有，和「目标 iOS 17、不用 beta API、不碰 Package.swift」三条红线冲突。只吸收原则（内容优先、控件抬升、同心圆角、左对齐字号层级），这些零成本。

**它会想让滑块和频谱刻度对齐。** 不要。滑块用 `M = round(1 + 255p²)`，频谱是线性 k 轴，两者不对齐是已知取舍——低阶需要精细控制。视觉上传达"对称向外扩张"就够了。

**它可能会把平均偏离写回"最远差"。** 不要。最大逐点误差不随 M 单调，本工程测试形状在 M = 17、20、28、30 处就会回升。用尾部能量 RMS，见 `V2_SCOPE_LOCK.md` 第四节。

## rev.1 → rev.2 改了什么

1. 平均偏离改用尾部能量 RMS（原来的最大逐点误差不单调，验收永远过不了）
2. `Math/` 改为完全只读（新口径不需要动 `TrailCache`）
3. 差量高亮的旧轨迹改为 `ContentView` 快照数组，画布不再重算
4. Prompt 25 补上 `ContentView`，拆成两个有序子步骤
5. Prompt 26 砍掉三个跨组件闪动，只保留三句字幕
6. 差量高亮收紧为只由 ⊕ 单步触发
7. "只有 Prompt 24 可跨文件"改为"每一步只改一个文件"
8. 路径更正：`ContentView.swift` 在包根目录；`AGENTS.md` 在仓库根目录，只追加不新建
9. Prompt 23 明确滑块实现为自绘轨道 + 透明原生 Slider
10. 画布标注改为一个合并的无障碍描述
