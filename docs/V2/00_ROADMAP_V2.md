## 各阶段验收信号

### Prompt 20 · iPad 布局

**信号**：模拟器 iPad 横屏下，频谱和滑块在屏幕底部通栏，65 根柱清晰可数，画布明显变宽。窗口拉窄到 800pt，无缝回到原右侧栏布局且外观无任何变化。

**最容易错**：把新分支写成改造旧分支。发现自己在动 500–900pt 那段代码就停下重做。

### Prompt 21 · 逐符号释义

**信号**：公式下方四行对照，拖滑块时第四行数字跟着变，且是灰的不是红的。系统字号调到最大不重叠不出界。

### Prompt 22 · 画布锚点标注

**信号**：三条带引线的标注落在图形外侧空白处不压墨迹；最大的圆外侧有带箭头的弧。换三个预设、手绘歪扭形状，标注自动避让；VoiceOver 朗读 `ContentView` 中既有的合并画布描述。

**最容易错**：转向弧方向画反。正频率画面上逆时针，负频率顺时针——屏幕 y 轴向下这一层翻转很容易漏掉。

### Prompt 23 · 步进按钮

**信号**：连按五次 ⊕ 阶数一次涨一格，墨迹每次都有可见变化；反函数往返断言 print 全绿。

**范围提醒**：⊕ 要先调用显式初始化参数 `onIncrease(oldM, newM)` 再更新 M；不在 `onChange(of: m)` 里推测来源。

### Prompt 24 · 差量高亮

**信号**：按一次 ⊕，四件事同时发生——新的两个圆变红、旧墨迹留灰影、公式下方出现 `+2 项 k = …`、0.9 秒后红色干净褪尽。按 ⊖ 与连续拖动滑块**不**触发。

**任何一件没发生就停下来查，不要继续往下做。** 三步必须分开编译。

**最容易错**：想在画布里用 `previousM` 重算旧轨迹。工程里 `TrailCache` 是每次重建时新建的临时对象，画布拿不到历史缓存，重算只能每帧新建缓存，必然掉帧。正解是 `ContentView` 在 M 改变前把当前 trail 数组原样快照一份。

### Prompt 25 · 平均偏离读数

**信号**：拖滑块时数字严格不回升，拖到 256 趋近 0，拖动依然跟手；全域 print 输出确认非增。

**最容易错**：写成最大逐点误差。那个量不单调，本工程测试形状在 M = 17、20、28、30 处就回升，验收永远过不了。用尾部能量 RMS，M 变化时直接遍历 512 个系数，不建后缀表。

**第二个坑**：把计算放进 `Canvas` 绘制闭包，或复制一份缩放公式。状态存数学单位，只在 ≥ 900pt 布局复用现有 `paperScale(for:in:)` 转成 pt。

### Prompt 26 · 首轮字幕

**信号**：冷启动依次出现三句；中途碰一下屏幕，字幕立刻消失且不再出现；字幕存在期间画布手绘与滑块拖动照常响应。

**范围提醒**：rev.1 的三个跨组件闪动（圆链提亮 / 连杆闪 / 滑块跳）已全砍。字幕的 `TimelineView` 只计算当前第几句，独立 `.task` 等待 8 秒；取消时必须 `catch { return }`，不得用会继续调 `onFinished` 的 `try?`。
