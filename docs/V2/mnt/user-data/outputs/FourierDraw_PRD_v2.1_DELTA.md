## 〇、为什么有这一版

两条反馈：

1. 评委在 iPad 上打开。v2.0 的「常规宽度」布局把公式、正弦条、浮层面板压进右侧 320pt 一栏，65 根频谱柱柱心间距只有 5pt，读不出也点不准。
2. 用户看完动画的反应是「挺好看」而不是「我懂了」。符号和画面之间没有一条可见的对应线，滑块只能连续拖，看不清一阶一阶到底加进来了什么。

第二条是主要矛盾。v2.0 的产品目标（三分钟内看懂三件事）没有变，变的是**兑现这个目标的手段还不够**。

Apple 在 WWDC26 的设计原则里有一条正好适用：简单不等于极简，有时候让界面更简单意味着往里加上下文和信息，人才能做出有依据的判断。本次全部是加信息，不是减。

## 二、新增功能

优先级沿用 v2.0 口径：**P0** 不做不能交付 · **P1** 直接影响评分 · **P2** 时间不足第一批砍

### F13 · iPad 横屏布局（P1）

容器宽度 ≥ 900pt 时启用。画布居左占剩余宽度，右侧固定 416pt 栏承载公式区、释义、正弦条与平均偏离读数，频谱与滑块合并为屏幕底部的通栏浮层面板（高 172，圆角 22）。

500–900pt 沿用 v2.0 的右侧栏布局，< 500pt 沿用讲义倒序。**新增分支不得改动既有两档的任何行为。**

纸底仍铺满全屏并延伸到面板背后；公式与正弦条仍印在纸上，不进浮层面板。

频谱柱心间距在 1180pt 下约 17pt。命中测试仍为整条挂单一 `DragGesture` 反查最近 k。

### F14 · 公式逐符号释义（P0，教学核心）

公式下方常驻四行对照：`cₖ` → 这个圆有多大；`e^(i2πkt)` → 转多快、朝哪边转；`Σ` → 把它们首尾接成一条链；`|k| ≤ M` → 链子只搭到第 M 阶为止。

第四行的 M 跟随滑块变化但**不上朱砂**。整条界面里只有主公式那个 M 是红的。

配套在画布上挂三条锚点标注，用「符号 + 大白话」的形式贴在它命名的那个元素旁边，一条发丝引线相连。标签必须落在原稿幽灵包围盒之外，位置从几何实时推导，不得硬编码。容器高度 < 560pt 时隐藏。

**不使用编号标记。** 编号服务于序列，这里是对应关系。

### F15 · 阶数差量高亮（P0，教学核心）

**触发条件：只由 ⊕ 单步按下触发。** `HarmonicSlider` 通过 `onIncrease(oldM, newM)` 在 M 改变前把事件传给 `ContentView`；不在 `onChange(of: m)` 里推测来源。⊖、连续拖动滑块、空闲轮播、切换预设、手绘完成一律不触发。这样新增集合恒为两项 `{+M₁, −M₁}`（`M₁ = 256` 时只有 `−256` 一项），读数模板才成立；也符合「一阶一阶看」的语义。

旧轨迹由 `ContentView` 在 M 改变**之前**把当前 trail 数组原样快照为 `previousTrail: [CGPoint]`，画布只负责绘制。**不得在画布里重算**——工程中 `TrailCache` 是每次重建时新建的临时对象，画布拿不到历史缓存。

触发后 900ms 内：

- 新纳入的 `±M₁` 两个圆以朱砂描边（1.6pt，0.95）
- `trail_{M₀}` 以 `ink.opacity(0.09)` 留在底层
- 公式下方出现 `+N 项` / `k = +M₁ 和 k = −M₁` / `半径 a pt 与 b pt`
- 平均偏离读数显示 `旧值 → 新值`，新值上朱砂

**新增项数必须从实际频率集合取差集**，不得用 `2M+1` 推算：M = 256 时只多一项 `−256`。

**900ms 后朱砂必须完全褪尽**，不允许残留。

常驻补一行灰字：「两边频率对称，半径通常并不相等」——这是 v2.0 第四节第 3 条数学事实的界面化，不随差量消失。

### F16 · 阶数步进按钮（P0，教学核心）

面板标签行右端一对 28pt 按钮（热区补 44 × 44），⊖ / ⊕ 各令 M 减一 / 加一，夹紧在 1…256。左侧一行 11pt 灰字「一阶一阶看」。

滑块绑定值仍是 \(p\)，步进走反函数 \(p' = \sqrt{(M'-1)/255}\)，必须验证对 M ∈ [1, 256] 全域往返一致。

滑块同时改为中心向外对称生长，中点刻度对齐频谱 k = 0。

> 滑块用 \(p^2\) 映射、频谱是线性 k 轴，两条刻度不严格对齐。这是有意保留的取舍：低阶需要精细控制。视觉上传达对称扩张即可，**不得为对齐而修改映射公式**。

### F17 · 平均偏离读数（P1）

**rev.1 定义为最大逐点误差并要求其随 M 单调下降，该定义作废。** 最大逐点误差不是单调量，在本工程自己的测试形状上 M = 17、20、28、30 处即出现回升，验收条件永远无法稳定通过。

改用**尾部能量 RMS**。由 Parseval：

\[
E(M) = \sqrt{\sum_{|k| > M} \left| c_k \right|^2}
\]

每加一阶从尾部减去一个非负项，因此随 M 严格非增。M ∈ [1, 256] 已全量验证零反例。

实现：M 或系数变化时，直接遍历已有 512 个 `[Epicycle]` 求尾部能量。不建后缀表，不为这点开销增加缓存状态，`Math/` 保持完全只读。

界面：读数只在 ≥ 900pt 新 iPad 布局显示。状态存数学单位的 \(E(M)\)，显示时调用现有共享纯函数 `paperScale(for:in:)` 转成 pt，不复制缩放公式。主标签「墨迹与原稿的平均偏离」，提示行「阶数每加一阶，这个数不会变大」。某阶系数可能为零，一位小数也可能让相邻两阶显示相同，因此不得写「一定变小」，也不得再称「最远差」。

只在 M 变化时计算，结果存进 `@State`。**禁止放进 `Canvas` 绘制闭包。**

计算时机、`@State` 与缩放系数 `s` 都在 `ContentView`，因此本条实际涉及 `ContentView.swift` 与 `FormulaHeader.swift` 两个文件。

### F18 · 首轮引导字幕（P1）

冷启动后 8 秒内，画布下方浮一张卡片依次显示三句。任何一次交互立即淡出，整个会话不再出现。

**rev.1 曾要求配三次跨组件画面动作（圆链提亮 / 连杆闪 / 滑块跳），已全部砍掉。** 那需要改 `PaperCanvas` 与 `HarmonicSlider`，且工程中两个 `TimelineView` 分别封装在画布与正弦条内部，不存在可复用的共享 timeline。字幕组件的 `TimelineView(.periodic(by: 0.1))` 只计算当前字幕；独立 `.task` 等待 8 秒后结束，视图提前移除时必须正确处理取消，不得用会吞掉 `CancellationError` 的 `try?`。

字幕必须 `.allowsHitTesting(false)`，存在期间画布手绘与滑块拖动照常响应。

**它不是教程页**，不拦交互、无按钮、无关闭控件，因此不违反 v2.0 第 3.2 节「不做教程页」。

`accessibilityReduceMotion` 打开时照常显示，去掉交叉淡入。

## 四、朱砂用量复核

v2.1 之后朱砂出现在：滑块旁的活数字 M、差量窗口内新增的两个圆与对应频谱柱、差量读数里的新值、选中项的圆与柱与单项公式、正弦条上的同步相位点、收笔完成印。

全部落在 v2.0 §3.1 的两条用途内（当前被操作或选中的量 / 收笔完成印）。差量高亮属于第一条——它标记的是「刚刚被这次操作纳入的量」。

判据不变：**它标记的是一个状态，不是在增加视觉趣味。**
